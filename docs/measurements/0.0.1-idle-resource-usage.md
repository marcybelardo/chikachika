# 0.0.1 idle resource usage

**Measured:** 2026-09-02

## Scope

This is a representative observation of the source-built, release-optimized
`0.0.1` application while idle. It is evidence for the milestone completion
gate, not a cross-platform performance benchmark.

The application had a saved overlay loaded and its OBS Browser Source
connected. After a 30-second settling period, neither Chikachika nor OBS was
used during the sample window.

## Environment

- Chikachika commit: `616116bf7a8dd00d2024192eb1c74325d75bbe65`
- Build: `cargo build --release`, launched as `./target/release/chikachika`
- Operating system: NixOS 26.05 (Yarara), x86_64
- Kernel: Linux 6.18.45
- Processor: AMD Ryzen 5 3600 6-Core Processor, 12 logical CPUs
- System memory: 31 GiB, with no configured swap
- OBS Studio: 32.1.2

## Method

The process was sampled once per second for 60 seconds with procps-ng `top`:

```sh
app_pid=$(pgrep -n -x chikachika)
top -b -d 1 -n 60 -p "$app_pid"
```

Resident set size (`RES`), process CPU percentage, process state, and elapsed
CPU time were extracted from each Chikachika process row. Memory values from
`top` are in KiB and are converted here using 1 MiB = 1024 KiB.

## Limits

This observation covers one Linux host, one release-optimized source build,
and one minute of idle behavior with OBS connected. It does not characterize
startup, active editing, long-running memory growth, macOS resource use, or
performance on different hardware. Those scenarios can be measured later if
product behavior or field reports justify a broader performance investigation.
